## Verifying changes

There is no test runner configured (no Vitest/Jest). Verify from the repo root (turbo runs each app's script):

```bash
pnpm typecheck           # tsc --noEmit per app (strict, noUnusedLocals/Parameters)
pnpm lint                # eslint per app (frontend: @tanstack/eslint-config)
pnpm check               # prettier --check over the whole repo
pnpm build               # frontend: vite + nitro build
```

Add `--filter frontend` (e.g. `pnpm typecheck --filter frontend`) to scope to one app.

For runtime checks, `pnpm dev` serves on port 3000; SSR output can be checked with `curl localhost:3000/<route>`.

## Conventions that bite

Paths below are relative to `apps/frontend/`.

- **Route tree is generated.** `src/routeTree.gen.ts` is regenerated by the Vite plugin on `pnpm dev`/`pnpm build`, or manually via `pnpm generate-routes`. A new route file won't typecheck (`createFileRoute('/x')` path errors) until it's regenerated. The file is read-only in VS Code settings.
- **Route path string must match the file path**: `src/routes/demo/schedule.tsx` → `createFileRoute('/demo/schedule')`.
- **Type-only imports must use `import type`** (`verbatimModuleSyntax` is on).
- **Path aliases**: `#/*` (package.json `imports`) and `@/*` (tsconfig) both map to `src/*`.
- **Router context carries `queryClient`** (typed via `createRootRouteWithContext<MyRouterContext>` in `__root.tsx`), so loaders call `context.queryClient.ensureQueryData(...)` rather than importing a client.
- **API endpoints** use the `server.handlers` property on `createFileRoute` (e.g. `src/routes/api/*.ts`), not a separate API folder.
- Files under `src/routes/demo/` are scaffold demos and can be deleted, along with their links in `src/components/Header.tsx`.
- Theme (light/dark/auto) is set by an inline script in `__root.tsx` before hydration plus `ThemeToggle`. Colors are CSS variables in `src/styles.css` (`--sea-ink`, `--line`, etc.) used via Tailwind arbitrary values.
